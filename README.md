## 4. 전체 시스템 구조 및 모듈 계층도 (System Architecture & Hierarchy)

|:---|:---|:---|

| **통신부 (Comm)** | `UART_TX`, `UART_RX`, `FIFO`, `ASCII_Sender` | 직렬-병렬 데이터 변환(SerDes), 송수신 속도 차이 극복을 위한 선입선출 버퍼(FIFO), 이진 데이터의 ASCII 문자 인코딩 제어 상태 머신 |
| **제어/입력부 (Control)**| `Btn_avg_controller` | 외부 스위치 조작 시 발생하는 기계적 진동(Chattering) 현상을 제거하기 위한 디바운싱(Debouncing) 회로 및 에지 검출(Edge Detection) 논리 |
| **데이터 처리 (Datapath)**| `Watch`, `Stopwatch`, `SR04_Ctrl`, `DHT11_Ctrl` | 시스템 클럭 분주기(Clock Divider) 기반 실시간 누적 연산, 초음파 Echo 펄스 기반 거리 수치화 연산, 1-Wire 규격 기반 40bit 직렬 데이터 수신 및 파싱 회로 |
| **디스플레이 (Display)** | `BCD_to_FND` | 4비트 BCD 논리 값을 8비트 7-Segment 디스플레이 점등 신호 패턴으로 매핑하는 다중화 조합 논리 회로(Combinational Logic) |

### 5.6 최종 결론 및 타이밍 디버깅 (Timing Optimization)

![스크린샷 2026-06-04 193131.jpg](./스크린샷 2026-06-04 193131.jpg)

| 구분 | 상세 설명 |
|:---|:---|
| **모듈 명** | **타이밍 클로저(Timing Closure) 및 데이터 경로 최적화 (PPA 개선)** |
| **발생 이슈** | `ASCII_Sender` 내부 로직 설계 시 나눗셈(`/`) 및 나머지(`%`) 연산자를 직접 사용하여 논리 합성(Synthesis)을 수행한 결과, 데이터 처리 경로가 지나치게 길어지는 현상이 발생했습니다. 이로 인해 Setup Time 위반(Worst Negative Slack -2.86ns) 현상과 대량의 LUT 물리 자원이 낭비되는 설계 결함이 확인되었습니다. |
| **해결 방안 및 고찰** | 단일 클럭 사이클 내에서 이뤄지는 복잡한 나눗셈 로직을 제거하고, 상태 머신 상에서 여러 사이클에 걸쳐 수행되는 순차적 뺄셈 기반 알고리즘으로 구조를 재설계하였습니다. 결과적으로 Worst Negative Slack이 양수(+0.167ns)로 전환되어 타이밍 요구 조건이 성공적으로 충족(Timing Closure)되었으며, LUT 면적 또한 대폭 감소되는 면적 및 속도 최적화(Area/Delay Trade-off)의 실무적 검증을 완료하였습니다. 추가로 DHT11 수신부에서도 Shift Register 방식과 MUX 방식 간의 하드웨어 PPA를 비교 분석하여 최적 구조 설계의 당위성을 입증하였습니다. |

| **모듈 명** | **DHT-11 데이터 수신 구조 개선 (Shift Register vs MUX 방식 비교)** |
| **발생 이슈** | 온습도 센서(DHT11)로부터 연속적으로 수신되는 40비트의 직렬(Serial) 데이터를 내부 병렬(Parallel) 레지스터에 저장하는 구조를 설계함에 있어, 데이터 할당 방식에 따른 하드웨어 면적(LUT) 및 타이밍 성능(Worst Negative Slack, WNS)의 트레이드오프(Trade-off)를 분석하고자 하였습니다. |
| **해결 방안 및 고찰** | **접근 1 (Shift Register 방식):** 새로운 비트가 입력될 때마다 기존 데이터를 시프트(Shift)하여 40개의 플립플롭(F/F)을 직렬로 연결하는 구조입니다. 배선(Routing) 경로가 단순화되어 추가적인 제어 논리가 거의 필요하지 않으므로 LUT 사용량이 현저히 감소하며, WNS가 증가하여 타이밍 여유(Timing Margin)를 안정적으로 확보할 수 있습니다.<br>**접근 2 (비트 위치 직접 지정 방식):** 카운터 값에 따라 멀티플렉서(MUX) 구조를 활용하여 40비트 중 특정 레지스터 인덱스에 데이터를 직접 할당하는 방식입니다. 매 비트마다 주소 디코딩 및 선택 논리가 필요하여 회로가 복잡해지며, 이로 인해 물리적 LUT 자원 소모가 증가하고 논리 단계(Logic Depth)가 깊어져 WNS가 감소(성능 저하)하는 현상이 발생합니다.<br>**결론:** 다량의 직렬 데이터 수신부 RTL 설계 시에는 MUX 기반의 직접 지정 방식보다 Shift Register 구조를 채택하는 것이 데이터 경로(Datapath) 지연을 최소화하고 면적을 최적화(Area Optimization)하는 정석적이고 효율적인 하드웨어 아키텍처임을 논리 합성 결과를 통해 실증적으로 검증하였습니다. |
